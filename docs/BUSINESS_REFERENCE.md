# 레퍼런스 비즈니스 모델: 푸드팡(Foodpang)

> 베지왕의 참고 모델. 출처: foodpang.co (2020~2022 보도자료 3건).

## 1. 푸드팡 모델 요약

- **정체성**: 식당 ↔ 도매시장(중도매인) 직거래 **B2B 식자재 커머스** ("식자재 아마존").
- **거점**: 2018 부산(반여·엄궁) 시작 → 2019 서울/**가락시장** 진출. 이유: 전국 산지가 가락을 거쳐 지역으로 재분배되는 허브 구조.
- **작동**: 식당이 앱으로 발주 → 가락·부산 도매시장 기반 **무료 새벽배송**. 야채·과일·축수산·공산품 **11,000 SKU**, **도매시세 매일 업데이트**, 품질 불만족 **100% 교환/환불**.
- **성장**: 5,000+ 식당, 월매출 20억(2021.11), **시리즈B 110억(누적 160억)** — KDB산업은행·하나·IBK·SBI인베스트먼트.
- **해자 1) 물류**: **FMFC**(Fresh Micro Fulfillment Center) 신선 물류 거점 확충.
- **해자 2) 데이터**: 2021 한국지능정보사회진흥원 **'식품유통물류 빅데이터 센터'** 국가과제 선정 → 시세변동·유통 데이터 오픈포맷 제공, **aT 빅데이터 플랫폼 연계**. (표준 분류체계 부재가 난제였음)
- **목표**: 전국 33개 도매시장 디지털 인프라 + **시세 예측** 기술 투자.

## 2. 베지왕에의 시사점

| 축 | 푸드팡 | 베지왕 포지션 |
|---|---|---|
| 고객 | **B2B(식당)** — 고빈도·고LTV | **B2C(일반 소비자)** — 푸드팡이 비어있는 영역, "경락가 나침반"으로 진입 |
| 진입 훅 | 저렴한 식자재 + 새벽배송 | **정보 비대칭 해소(나침반)** = 무자본 획득 채널 |
| 수익화 | 식자재 거래 + 물류 마진 | 니즈 DB → **공동구매/산지직송/사입·판매**(이미 로드맵에 있음) |
| 데이터 | 빅데이터 센터, aT 연계, 시세 예측 | `raw_auction` 축적 → **자체 평년가·시세 예측**(DATA_SOURCES.md 설계와 일치) |
| 해자 | 물류(FMFC) | 초기엔 데이터/커뮤니티, 거래 확장 시 픽업·제휴 물류 |

**핵심 교훈**
1. **시세 정보는 훅, 돈은 거래+물류+데이터에서 난다.** 나침반(B2C)로 트래픽·니즈DB를 모으고 → 거래로 전환하는 궤적은 푸드팡의 "시세 매일 업데이트 → 커머스 → 물류 → 데이터" 궤적과 동일 논리.
2. **데이터 자산이 별도 사업/투자 포인트.** 푸드팡이 시세 데이터로 국가과제·투자를 받았듯, 우리의 경락가 이력 + 소비자 니즈 DB는 그 자체가 자산.
3. **가락 허브 집중 시작이 정석.** 이미 그렇게 설계됨.
4. **차별화 = B2C + 유통 투명성.** 푸드팡은 B2B 효율/물류, 베지왕은 소비자 편의 "지금 사도 되나?" + "소매 거품" 폭로.

## 3. 정해야 할 방향(오픈 이슈)

- **1차 타깃**: (A) B2C 소비자 정보/공동구매 vs (B) 소상공인/식당 발주까지. → 현재 프론트/데이터는 (A) 기준.
- **수익 모델 1순위**: 공동구매 수수료 / 산지직송 중개 / 데이터 구독(B2B) 중 무엇을 먼저?
- **물류 관여도**: 정보만 → 중개 → 직접물류 중 어디까지.

> 결론: 푸드팡을 "B2B로 먼저 증명된 도매시장 디지털화"의 레퍼런스로 삼되, 베지왕은 **B2C 소비자 나침반 → 니즈 DB → 거래**로 차별화. 정보 레이어(나침반)와 데이터 자산(경락가 DB)은 이미 구축 방향이 정합적.
