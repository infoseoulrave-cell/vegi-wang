## 1. 가락시장 경매결과 ✅

`garak.co.kr/homepage/publicdata/dataJsonOpen.do` · 계정(id/passwd) + dataid

응답 행 필드와 활용 상태:

| 필드 | 뜻 | 쓰는가 |
|---|---|---|
| `PUMMOK` | 품목명 | ✅ 매칭 키 |
| `PUMJONG` | 품종명 | ⬜ 미사용 — **품종별 가격 분해 여지** |
| `UUN` | 거래단량 | ✅ 원/kg 환산의 근거 |
| `DDD` | 등급 | ✅ 특·상만 채택 (소매 등급과 정합) |
| `PPRICE` | 경락가 | ✅ 대표값 |
| `SSANGI` | 산지 | ⬜ 미사용 — **산지별 가격차 노출 여지** |
| `ADJ_DT` | 정산일자 | ⬜ 미사용 |

- 조회 단위가 **품목 × 6개 법인**이라 호출량이 많다. 40품목이면 240회.
- 청과 법인만 있어 **수산·축산은 나오지 않는다.**
- 거래량 필드가 없어 물량 가중평균이 불가능하다 (aT에는 있다).

## 2. KAMIS 일별 부류별 도·소매가격 ✅

`kamis.or.kr/service/price/xml.do` · `p_cert_key` + `p_cert_id`

| 필드 | 뜻 | 쓰는가 |
|---|---|---|
| `item_name` | 품목명 | ✅ 매칭 키 |
| `rank` | 등급(상품/중품) | ✅ 상품 우선 |
| `unit` | 규격·단위 | ✅ 축 환산 |
| `dpr1~dpr4` | 당일·1일·1주·2주전 | ✅ 시계열 (중량단위면 이미 원/kg) |
| `dpr5, dpr6` | 1개월·1년전 | ✅ 시계열 (거래단위 → 환산 필요) |
| `dpr7` | 평년가 | ✅ 부트스트랩 기준선 |
| 부류코드 | 100~600 | ⚠ 200/400/600만 조회 중 |

- **도매(02)와 소매(01) 양쪽**을 준다. 유통 거품 지표의 소매 축이 여기서 온다.
- 전국 조사 표본이라 **가락 한 시장과는 지역 범위가 다르다** (아래 §5 참고).
- 도매는 축이 슬롯마다 달라 **주 원천으로 쓰지 않는다.** 교차검증·부트스트랩 전용.

## 3. aT 전국 공영도매시장 ❌ (키 대기)

전국 32개 시장 + **거래량**을 한 번의 호출로 준다. 가락 대비 이점:

- 품목별 반복 호출 불필요 → 호출량이 1/240로 줄어든다
- 거래량으로 **물량 가중평균** 가능
- 수산 도매시장도 포함 (부산 국제수산 등)

⚠ 응답 필드명은 명세서가 xlsx 첨부라 미확정. `/api/debug/at-market`이 확정한다.

## 4. 해수부 위판장 ❌ (키 대기)

수산 경락가의 유일한 원천. `csmtAmount ÷ csmtWt`로 **단위 파싱 없이** 원/kg가 나온다.

## 5. 아직 안 쓰고 있는 정보 (확장 여지)

우선순위 순.

1. **산지(SSANGI / orgplceSeNm)** — "같은 배추라도 강원산이 얼마, 전남산이 얼마".
   소비자에게 바로 와닿고 데이터는 이미 들어오고 있다. 코드 변경만 필요.
2. **품종(PUMJONG)** — 사과 후지/홍로, 배 신고 등. 지금은 품목으로 뭉뚱그린다.
3. **위판장·시장별 가격차** — aT/위판장이 열리면 "어느 시장이 싼가"가 가능해진다.
4. **거래량(QTY / csmtQy)** — 물량 가중평균은 이미 구현했지만, 물량 자체를
   "오늘 많이 나온 품목" 같은 신호로 쓸 수 있다.
5. **KAMIS 미조회 부류** — 아래 §6.

## 6. 품목 확장 후보

KAMIS 부류는 6개인데 우리는 3개만 조회한다. 판단 기준은 하나다 —
**경락가 원천이 있는가.** 우리 서비스는 도매 대 소매 비교가 핵심이라
소매만 있는 부류는 넣을 수 없다.

| 코드 | 부류 | 경락가 원천 | 판단 |
|---|---|---|---|
| 100 | 식량작물 | 부분 | **감자·고구마는 가락 청과 거래 → 확장 후보.** 쌀·콩은 양곡이라 불가 |
| 200 | 채소류 | ✅ | 서빙 중 |
| 300 | 특용작물 | 부분 | **버섯류(느타리·팽이·새송이)는 가락 거래 → 확장 후보** |
| 400 | 과일류 | ✅ | 서빙 중 |
| 500 | 축산물 | ❌ | 축산물도매시장 별도 체계 — 원천 없음 |
| 600 | 수산물 | ✅ | 서빙 중 (원천은 위판장) |

감자·고구마·버섯은 **장바구니 핵심 품목인데 지금 아예 없다.** 가장 큰 누락이다.

확인 방법 (KAMIS 키는 이미 살아 있으므로 배포 후 바로 가능):

```
GET /api/debug/kamis-catalog?codes=100,300
```

`candidates` 배열이 도매·소매가 모두 있고 가공식품이 아니며 아직 카탈로그에
없는 품목만 걸러서 준다. 그 목록의 **실제 품목명·단위**를 보고 카탈로그에
넣는다 — 추측으로 추가하지 않는다.

※ `ProduceCategory`가 채소/과일/수산 3종 union이므로, 부류를 늘리면
탭·카테고리 페이지·이미지까지 함께 손봐야 한다. 확인 후 별도 작업.

## 8. 가격 비교 시 남아 있는 한계

수정된 항목은 [DEVLOG Chapter 4](../DEVLOG.md) 참고. 아래는 **아직 남은** 것들.

### 8-1. 지역 범위 불일치 (경락 vs 소매)

경락가는 **가락시장 한 곳**, 소매가는 **KAMIS 전국 조사**다.
거품배수는 "서울 가락 도매 대비 전국 소매"라는 뜻이지 동일 지역 비교가 아니다.

→ aT가 열리면 시장별 경락가가 생기므로 지역을 맞출 수 있다.

### 8-2. 유통 단계 불일치 (수산)

수산 경락가는 **산지 위판가**이고 소매가는 **전국 소매**다.
청과(도매시장 → 소매)보다 단계가 하나 더 많아 **배수가 구조적으로 크게 나온다.**
수산 거품배수를 청과와 같은 임계값(1.8 / 2.5)으로 판정하면 과대평가된다.

→ 축이 정상화된 뒤 실측 분포를 보고 **카테고리별 임계값**을 따로 잡아야 한다.

### 8-3. 소매 단위 환산의 왕복 오차

KAMIS 소매가 "1포기" 같은 개수 단위로 오면 카탈로그 중량으로 나눠 원/kg를
만들고, 표시할 때 다시 곱한다. 왕복이라 값 자체는 보존되지만,
**카탈로그 중량이 틀리면 원/kg 축의 소매가가 함께 틀어진다.**

→ 개수 단위 품목의 `kgPerConsumerUnit`은 검증 우선순위가 높다.

### 8-4. 거품 임계값이 아직 실측 기반이 아니다

1.8 / 2.5는 축이 깨져 있던 시기에 정해진 값이다.
정상화 후 `/api/debug/price-axis`의 `retailMultiple` 분포를 보고 재조정해야 한다.
